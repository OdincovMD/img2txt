# Шаг 3. Ранжирование важных признаков

Это центральный исследовательский шаг проекта.

## Постановка задачи

Нужно по признаковому описанию изображения предсказать top-k меток из словаря активных признаков, которые врач посчитал бы диагностически важными.

- тип задачи: **multi-label ranking**
- целевой словарь: **24 активные метки**
- основная метрика: `Precision@10`, `Recall@10`

## Данные

- **Ручная разметка:** 400 изображений, по каждому до 10 экспертных меток.
- **Псевдо-разметка:** автоматически сгенерированные метки на основе отклонения признаков от популяции и эвристик.

## Эксперименты: нейросетевой этап

### 1. Базовый CNN-бейзлайн

Стартовая постановка была image-based:

- `efficientnet_b0`
- multi-label BCE
- top-k ранжирование по выходному вектору вероятностей

**Результат:** базовый уровень около `0.40`, затем быстрое плато.

### 2. `pos_weight` и focal loss

Пробовали компенсировать дисбаланс меток через:

- `pos_weight`
- focal loss
- более агрессивную регуляризацию

**Наблюдение:** локально `pos_weight` мог казаться полезным, но дальше стало ясно, что для top-k ранжирования он скорее вреден, чем полезен.

**Вывод:** для ranking-задачи лучше обычный BCE без `pos_weight`.

### 3. Псевдо-разметка

Пробовали смешивать ручную и псевдо-разметку в обучении.

**Результат:** резкое ухудшение качества.

**Интерпретация:** "аномальный признак" не равен "клинически важному признаку".

**Вывод:** текущая псевдо-разметка не годится как прямой supervision.

### 4. Маска очага как дополнительный канал

Пробовали явно подавать сегментационную маску в CNN.

**Результат:** прирост отсутствовал или был в пределах шума.

**Вывод:** на этом масштабе данных и разрешении это не ключевой источник улучшения.

### 5. Аугментации

Отдельно выяснилось, что сильные аугментации вредят.

Критически важное наблюдение:

- **сдвиг hue недопустим**

потому что цвет сам является диагностическим признаком.

**Вывод:** лучше работает мягкая аугментация без hue shift.

## Эксперименты: сжатие пространства меток

После анализа разметки target space был сокращен до **24 реально используемых признаков**.

Это дало сразу несколько эффектов:

- задача стала проще;
- шумные редкие метки ушли;
- табличные модели начали показывать особенно сильные результаты.

Это был один из самых сильных переломных моментов всего проекта.

## Эксперименты: мультимодальная модель

Следующая гипотеза:

> если табличные признаки уже очень информативны, нужно объединить image branch и tabular branch.

Была собрана схема `CNN + tabular`.

**Результат:** заметный рост качества примерно до `0.61`.

**Вывод:** табличный сигнал несет огромную долю полезной информации, а изображение становится дополнительным источником.

## Эксперименты: переход к чисто табличным моделям

После мультимодального этапа возникла гипотеза:

> если почти весь сигнал уже есть в табличных признаках, image backbone можно убрать совсем.

Пробовали:

- `CatBoost`
- `XGBoost`

на табличных признаках без CNN.

### 1. CatBoost

CatBoost подтвердил, что задача хорошо решается табличным бустингом.

### 2. XGBoost

Ансамбль независимых бинарных XGBoost-моделей по меткам стал лучшим решением проекта на тот момент.

**Лучший зафиксированный результат:** около `0.62`.

## Что еще пробовали на табличном этапе

### 1. Разные feature set для XGBoost

Для XGBoost рассматривались разные пространства входных признаков:

- `numeric_only`
- `selected_buckets`
- `all_buckets`

Ключевое исследовательское наблюдение:

- search space гиперпараметров нельзя считать универсальным между этими режимами;
- checkpoint одного режима нельзя бездумно переносить на другой.

Это пока не сведено в полную численную таблицу, но уже зафиксировано как важный результат.

### 2. MLP на табличных признаках

Отдельно рассматривалась joint-модель:

- MLP с общим выходом на все метки;
- идея в том, что такая модель может естественно учитывать зависимости между таргетами.

Это остается отдельным направлением сравнения с бустингами.

## Новый экспериментальный трек: `xgb_classifier_chain`

Текущий baseline XGBoost решает задачу как набор из `24` независимых бинарных моделей.

Это сильный baseline, но у него есть ограничение:

- каждая метка предсказывается отдельно;
- модель не использует связи между совместно встречающимися важными признаками.

Из этого выросла новая гипотеза:

> если следующая модель будет видеть предсказания предыдущих, можно использовать зависимости между таргетами.

Для этого добавлен отдельный режим:

- **`xgb_classifier_chain`**

Идея:

- модели обучаются по цепочке;
- каждая следующая получает предсказания предыдущих как дополнительные признаки;
- на train-time используются OOF-предсказания, чтобы не было leakage.

**Статус:** режим подготовлен архитектурно, но итоговые экспериментальные числа еще не зафиксированы.

## Текущее состояние шага

На сегодня картина такая:

1. `CNN-only` оказался недостаточно эффективным.
2. `CNN + tabular` дал сильный прирост.
3. `Tabular boosting` оказался не хуже и даже лучше тяжелых нейросетей.
4. Лучший практический baseline сейчас — **XGBoost**.
5. Следующая главная гипотеза — **classifier chain для XGBoost**.

## Главные выводы по Шагу 3

1. Экспертная разметка незаменима.
2. Псевдо-разметка в текущем виде не отражает клиническую важность.
3. Для этой задачи табличное представление сильнее, чем казалось изначально.
4. Сжатие пространства меток критически важно.
5. Градиентный бустинг на табличных признаках сейчас является основным рабочим направлением.
